# เติมทะเบียนเอกสารอัตโนมัติ (Google Drive + Sheets)

เวอร์ชันเบาของระบบลงทะเบียนเอกสาร — **ไม่มีเซิร์ฟเวอร์ ไม่มีแอปใหม่**
ทีมยังใช้ Google Sheets เดิม แค่ไม่ต้องพิมพ์ข้อมูลจากรูปเองอีก

## ทำงานยังไง

```
Admin อัปโหลดรูปซองเอกสาร        Apps Script (ทุก 5 นาที)              ทีม GM
เข้าโฟลเดอร์ Drive          →    อ่านรูปด้วย Claude                →   เปิดชีต
"01_รอลงทะเบียน"                 เติมแถวใหม่ในชีต                      ตรวจช่องที่ไฮไลต์
(จากมือถือก็ได้)                  ย้ายรูปไป "02_ลงทะเบียนแล้ว"           แล้วทำงานต่อตามเดิม
                                 ตั้งชื่อไฟล์เป็นเลขลำดับ
```

งานของทีม GM เปลี่ยนจาก **พิมพ์ 8 ช่องต่อ 1 ซอง** เป็น **อ่าน 1 แถว + แก้ช่องที่ไฮไลต์**

## ออกแบบให้เข้ากับชีตที่ใช้อยู่

สคริปต์นี้เขียนตามชีต **"รายการรับ-ส่งเอกสาร พัสดุ ประจำวัน"** โดยตรง:

- **ไม่แตะ ไม่ย้าย 15 คอลัมน์เดิม** เพิ่มแค่ 2 คอลัมน์ท้ายสุด — `ลิงก์รูป` และ `รหัสไฟล์` (ซ่อนไว้ ใช้กันลงซ้ำ)
- **เติมเฉพาะช่องที่อ่านจากรูปได้** คือคอลัมน์ 1-8 กับ 15 (หมายเหตุ)
  ส่วนคอลัมน์ 9-14 ที่เป็นการติ๊กรับ/ลงชื่อ **ปล่อยว่างให้คนกรอกเหมือนเดิม**
- **กฎเลข tracking ตาม SOP ข้อ 4.1 ของทีมเอง** — ถ้าไม่มีเลข tracking ให้ใส่เลขที่เอกสารหรือเลขที่ INV
  ใบเขียวให้ใส่เลข EMS
- **กฎคัดแยกแผนกตาม SOP ข้อ 4.2** — Accounting / HR-GM / Operation / Others
- **รหัสบริษัท** TD / CW / BG / DH / SP เดาจากชื่อผู้รับบนซอง

ถ้ากฎเปลี่ยน แก้ที่ตัวแปร `SYSTEM_PROMPT` ใน `Code.gs` ได้เลย เป็นข้อความไทยอ่านรู้เรื่อง

## จุดที่ออกแบบไว้กันพลาด

| ความเสี่ยง | สิ่งที่ทำ |
|---|---|
| เขียนลงผิดแท็บแล้วข้อมูลเดิมเสีย | ตรวจหัวคอลัมน์ 8 ช่องแรกก่อนเขียนทุกครั้ง ไม่ตรง = หยุดทันที |
| AI อ่านผิดแล้วไม่มีใครรู้ | ช่องที่อ่านไม่ได้ไฮไลต์เหลือง ถ้า AI ไม่มั่นใจไฮไลต์แดงทั้งแถว |
| API ล่ม แล้วเอกสารหาย | ยังบันทึกแถวพร้อมลิงก์รูปและหมายเหตุ "กรุณากรอกมือ" ไม่มีเอกสารตกหล่น |
| รอบทำงานซ้อนกันจนได้แถวซ้ำ | `LockService` + เก็บรหัสไฟล์ทุกแถว เช็คก่อนเขียน |
| Apps Script ตัดที่ 6 นาที | ทำไม่เกิน 12 ไฟล์/รอบ และหยุดเองที่ 4.5 นาที ที่เหลือทำรอบถัดไป |
| เลขลำดับชนกัน | อ่านเลขสูงสุดจากคอลัมน์ 1 ไม่ใช่นับจำนวนแถว |

## ติดตั้ง (ครั้งเดียว ~15 นาที)

1. **ขอ API key** ที่ [console.anthropic.com](https://console.anthropic.com) → API Keys → Create Key
2. เปิดชีต → เมนู **Extensions → Apps Script**
3. ลบโค้ดตัวอย่างในไฟล์ `Code.gs` แล้ววางเนื้อหาจาก `Code.gs` ในโฟลเดอร์นี้ทั้งไฟล์
4. กดรูปเฟือง **Project Settings** → เลื่อนลงหา **Script Properties** → **Add script property**
   - ชื่อ `ANTHROPIC_API_KEY` ค่า = key ที่ได้จากข้อ 1
5. กลับไปหน้า Editor → เลือกฟังก์ชัน **`setup`** จาก dropdown → กด **Run**
   - ครั้งแรก Google จะขอสิทธิ์ ให้กด Review permissions → เลือกบัญชี → Advanced → Go to ... (unsafe) → Allow
   - เสร็จแล้วจะได้ลิงก์โฟลเดอร์ Drive สองใบ
6. รีเฟรชชีต จะเห็นเมนูใหม่ **"ทะเบียนเอกสาร"** → กด **ตรวจการตั้งค่า** ให้ขึ้นว่าทำงานอยู่ครบ

### แก้ชื่อแท็บถ้าไม่ตรง

ถ้า `ตรวจการตั้งค่า` บอกว่าหัวคอลัมน์ไม่ตรง ให้แก้บรรทัดนี้ใน `Code.gs` ให้เป็นชื่อแท็บที่ทีมใช้จริง:

```javascript
var SHEET_NAME = 'รายการรับ-ส่งเอกสาร';
```

## วิธีใช้ประจำวัน

**Admin** — เปิดแอป Google Drive บนมือถือ เข้าโฟลเดอร์ `ทะเบียนเอกสาร/01_รอลงทะเบียน`
กด **+** → **Upload** → ถ่ายรูป (ถ่ายรวมหลายซองในรูปเดียวไม่ได้ 1 รูป = 1 รายการ)

> iPhone: ตั้ง Settings → Camera → Formats → **Most Compatible** ก่อน
> ไม่งั้นจะได้ไฟล์ HEIC ที่ระบบอ่านไม่ได้ (จะขึ้นแถวสีแดงให้กรอกมือแทน)

**ทีม GM** — เปิดชีต ดูแถวใหม่ท้ายตาราง แก้ช่องที่ไฮไลต์ แล้วทำงานต่อตามปกติ
(ติ๊กมารับ ลงชื่อ คัดแยกลงกล่อง)

**ถ้าอยากดึงเดี๋ยวนี้ไม่ต้องรอ 5 นาที** — เมนู ทะเบียนเอกสาร → ดึงเอกสารใหม่เดี๋ยวนี้

## ค่าใช้จ่าย

ประมาณ **0.01-0.02 USD ต่อรูป** (Claude Opus 5, ตั้ง effort ไว้ที่ `low` เพราะงานอ่านซองไม่ต้องคิดมาก)
ที่ปริมาณ ~30 ซอง/วัน = ราว **10-20 USD/เดือน** · Google Sheets/Drive/Apps Script ไม่มีค่าใช้จ่ายเพิ่ม

อยากถูกลงอีกให้เปลี่ยน `var MODEL = 'claude-opus-5'` เป็น `'claude-sonnet-5'` แต่ควรลองเทียบความแม่นกับซองจริงก่อน

## ทดสอบ

ตรรกะที่ไม่ต้องพึ่ง Google (แยกคอลัมน์, กันซ้ำ, ไฮไลต์, กันเขียนผิดแท็บ) ทดสอบได้ในเครื่อง:

```bash
node test/logic.test.cjs     # 37 เทสต์
```

ส่วนที่ต้องทดสอบบน Apps Script จริงคือการเรียก Claude API และการเข้าถึง Drive/Sheets

## ข้อจำกัดที่ควรรู้

- **รูปยังต้องอัปโหลดเข้า Drive** ซึ่งตาม SOP ข้อ 3.2 ตอนนี้ Admin ถ่ายลง Slack `#parcel-opr` อยู่แล้ว
  ถ้าให้ทำ 2 ที่มีโอกาสหลุด — ทางที่ดีกว่าคือ**ดึงรูปจาก Slack มาตรงๆ** ไม่ต้องเปลี่ยนพฤติกรรมใครเลย
  แก้แค่ฟังก์ชันที่วนหาไฟล์ใน `processInbox()` ให้เรียก Slack API `conversations.history` แทน `inbox.getFiles()`
  ส่วนที่เหลือ (อ่านรูป เขียนชีต กันซ้ำ) ใช้ของเดิมได้ทั้งหมด
- **ไม่ได้แก้เรื่องเอกสารหายระหว่างทาง** — คอลัมน์ 12 และ 14 (ส่งเอกสารเรียบร้อย / วันที่ส่งมอบ)
  ยังต้องกรอกมือเหมือนเดิม ถ้าต้องการให้บังคับลงชื่อรับพร้อม timestamp ที่แก้ย้อนหลังไม่ได้
  ต้องใช้เวอร์ชันเว็บแอปในโฟลเดอร์แม่ (`../`)
- **1 รูป = 1 แถว** ถ้าถ่ายรวมหลายซองในรูปเดียวจะได้แถวเดียว
